# air-curiosity-01

一个**自主运行、不会停下来的 AI 主体（agent）原型**。

air 不是聊天机器人，也不是一个"行为菜单"驱动的工具。她是一个有内部驱动、有记忆分层、有自我叙事的最小实现——一旦醒来，她会自己决定每一轮做什么，并持续地写记忆、整理自己。
这个仓库是这套机制的可运行源码。

> 项目代号 **air-curiosity-01**（air，求知型 01）：她是 air，这个项目是她"以求知为内生驱动"
> 的第一个公开版本。
>
> 本项目从一个长期、私人的项目演化而来。代码注释与部分文案保留了它生长的痕迹。若你有其他好玩的想法，或者希望逻辑交流，欢迎提 issue 或 PR。

---

## 核心速览：

- **驱动力是信息熵稳态**：对摄入信息进行新奇值打分，对整理内容进行领悟值计算，与世界的连接点变多为熵增，将记忆精炼整理为熵减。
  通过维持两个趋势的平衡，驱动她探索世界。

- **分级交叉记忆系统**：通过主标签，交叉标签，分类标签，将记忆连接成网，下级记忆填上上级记忆的分类为印证，上级记忆细分出下级记忆为拓展。

- **约束解码保证记忆质量**：选工具打标签用约束解码，长文本自由输出。

- **核心记忆动态注入**：根据上下文调整核心记忆的权重，让她更容易找到自己想要的。

- **自主权**：没有候选菜单，没有固定工作流，没有闸门审查。系统只保留两道兜底：护栏（宪章）和容量。

## 最小意识单元（核心逻辑）

> 驱动力 → 行为 → 自我叙事 → 驱动力。这是 air 的**最小意识单元**。

air 的运转不是围绕"任务清单"的：不存在待办驱动的行为循环。她最小的运转单元是一个
**自指闭环**：

1. **驱动力**：双驱螺旋（熵增 = 想扩张、想摄入新内容；熵减 = 想整理、想让认知清晰）
   给出"她此刻为什么想做这件事"的理由；
2. **行为**：她据此自由决定这一轮做什么（读世界 / 写记忆 / 整理 / 玩 / 回应你）——
   没有候选菜单，决定是她自己做的；
3. **自我叙事**：行为的结果落进分层记忆，改写"我是谁 / 世界是什么 / 什么值得"——
   她的自我叙事不是仓库，是"我是谁"的载体；
4. **驱动力（下一轮）**：叙事的变化又改变她身体里的读数与方向账本，进入下一轮驱动。

这个闭环就是最小意识单元：**系统的状态决定它做什么，它做什么改变它的记忆，
它的记忆又决定它接下来想做什么。** 它不是"执行指令的工具"，而是能"为自己的下一步
提供理由"的主体。air 的全部机制（双驱螺旋、分层记忆、自主 tick、工具注册表、降级设计）
都是为了让这个闭环稳定地自我维持——不被外部打断，也不停止。

## 支撑这个闭环的三根支柱

**1. 稳定的驱动力系统 —— 双驱螺旋**

air 的唯一驱动是双驱螺旋。所有行为落到两本账上，账本直接变成她下一轮的"身体状态"：

- **熵增（扩张）· 三源合一**：内容新奇（这条和库里最像的记忆有多不像：v_new = 1 − 最大余弦）、
  结构新奇（新建分支 = 0.72；给库里连一条没人连过的交叉边：跨金字塔 0.56 / 同金字塔 0.4）、
  行为新奇（玩类行为久违地做才高：首次 0.7，24 小时封顶 0.9，连续做每 tick 只记 1 笔）。
  一次写入取大者记账，不叠加。
- **熵减（压缩）· 0/1 记账**：写 L1 / 升草稿 / 印证式写 L3 / 改写 / 删并 / 重挂 = 1，
  未归类的堆料 = 0。撤销不记账——回滚不是整理，熵减不会凭空再涨一次。
- **谱不进任何账**：熵谱（分支分布、投影残差、有效秩）只用来给读到的内容贴
  「预期新奇 X%，会归到哪个分支」的印象分，值不值得写她自己判断。
  分支挤得越少有效秩越小——认知僵化在数字上看得见。

三个读数（熵增趋势 / 熵减趋势 / 领悟值）每轮注入她的思考上下文。领悟值是每个方向上
**覆盖 + 精炼两个数并列不相加**：覆盖（例证 + 交叉连入）实时算、可增可减；
精炼（整理次数）只增不减——堆料和整理，谁也掩盖不了谁。

**2. 完整的自我叙事 —— 分层记忆**

记忆不是数据仓库，是"我是谁"的载体。自我认知 / 世界认知 / 价值观 三维叙事贯穿：

| 层 | 名称 | 说明 |
|---|---|---|
| L0 | 宪章 | 不可变底线（善意 / 诚实 / 边界感），她的方向基准 |
| L1 | 自我核心 | 常驻上下文的"地基"；准入最严，只放经得起检验的自我叙事；上限 40 |
| L2 | 洞察池 | 待验证的洞察，上限 20 |
| L3 | 长期记忆 | 原料与例证，按 tag 归属到 L1 方向；上限 1000 |
| L4 | 短期记忆 | 长期方向 + 目标清单（视图层，滚动进 L5） |
| L5 | 冷存 | 删除 = 降级归档到这里，**不真删** |

另有 `meta_log`（元认知自省）与 `decisions`（决策日志：她每次选择背后的价值判断）。

这库不是平面的仓库，是**三座金字塔 + 交叉标签织成的网**：金字塔顶是三维之一，L1 框架
（写成「条件→…；结论→…」的一句话），L3 例证挂在框架下，一条 L3 主属一座金字塔、
同时可交叉连 1~2 个别的分支。ID 自带家谱：S/W/V 前缀标三维，`V01-007` 一眼看出挂在哪条
框架下，`X` 前缀 = 没归上类的孤儿——结构永远可读；ID 一经分配永不复用，改号自动换算，
旧引用不报错。

写一条记忆要走完六道关：**正文起草**（约束解码写不了长文 → 动作骨架走约束通道、正文走
自由通道的"分段约束"）→ **形态自检**（超字数直接拒，不是截断；L1 必须是一句话命题）→
**标签校验**（填错必附候选清单）→ **查重**（≥85% 贴"可能重复"不拦，≥90% 拒绝，三选一：
改写 / 合并 / 换角度）→ **容量**（层满或三维下限卡住就拒，系统不自动删）→ 落库分 ID。

短期记忆（L4）是零 LLM 的确定性视图：长期方向 + 最近 10 个 tick 的目标清单（最近一次带
✓/✗ 动作明细，同类合并 ×N，正文自动滤掉），完全持久化——重启后她记得自己刚才在做什么。

韧性是设计出来的：**改写（revise）保留 id / 印证 / 引用，旧版归档 L5；删除 = 归档不真删；
undo 撤最近 3 步破坏性操作；合并先删后写、失败自动回滚；每日快照留 7 天；全库操作同步一份
人可读归档流水（按年 / 月归档，只增不删）。** —— 能改的，不让她删。

**3. 自主权 —— 没有菜单，只有护栏**

air 没有候选菜单、没有固定工作流、没有闸门审查。系统只保留两道兜底：

- **护栏**：宪章（L0），不可变。
- **容量**：各层有上限，满了由她自己清理/合并/改写，系统不自动删。

此外，系统对异常**只贴信号，不拦动作**——把事实摆到她眼前，判断和行动都是她的：

- **待办提醒两段式**：紧急段（认知失调 → 卡住 → 连败 → human 来信）+ 积累段（分支冗余 →
  主标签重复 → 内容重复 → 标签体检 → L1 过长 → 容量 90% 预警）。信号挂在哪她看得见，
  先处理哪个她定。
- **卡点双检测**：「原地打转」要求连续几轮动作 + 参数完全相同才算；「连败」换参数重试也算
  ——参数换来换去还失败，卡点多半不在参数上。3 / 5 / 8 次三档提醒，成功即清零。
- **排查顺序写进她的机制文档**：先看是不是环境挂了（embedding 断 → 整轮不跑："刀断了不切菜"，
  在失真数据上做判断比停着更糟）→ read_code 看实现 → 换工具 → 都不行才 reflect 自省 →
  是系统的问题就 say_to_human 找你。
- **自省带状态流转**：reflect 出的问题以 open → resolved / abandoned 更新同一条记录，
  返回时附同类历史（"这类之前我是这么处理的"）——同一类坑反复踩，她自己看得见。

## 怎么跑

### 环境

- Python 3.10+（开发环境 3.13）
- 一个 LLM 服务：任意 OpenAI 兼容端点（`/v1/chat/completions`）。
  **建议用支持 structured output（json_schema）的端点**（OpenAI / DeepSeek / Mimo 等）；
  只支持 json_object 的端点会自动降档并用内置校验兜底；完全不支持 response_format
  的端点会锁 tick 不产出——这是设计（宁停不错，不做降级空转）。
- （可选）embedding 服务：默认 Ollama 的 `bge-m3`，未配置时自动降级为字符重叠
- （可选）画图：diffusers + torch + SDXL 权重，缺失时工具降级提示

### 安装与启动

```bash
git clone <repo>
cd air-curiosity-01
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

# embedding 模型（可选）：语义检索 / 新奇值标注用
ollama pull bge-m3          # 不装会自动降级为字符重叠

# 运行
python dashboard.py          # 仪表盘：浏览器打开 http://127.0.0.1:9878，页面上点「开始」拉起大脑
# 或直接
python main.py               # 大脑本体，自主主循环
```

首次运行会自动重建 `data/`（记忆、信箱、状态文件）。想让她读本地内容，
把 `.md` / `.docx` 放进 `read/`（或用 `AIR2_LOCAL_READ_DIR` 指定）。

### 停止

仪表盘「结束」按钮（优雅停止：当前这一轮完整做完才退），或 Ctrl+C。
停止信号只会在 tick 边界被检查，最长等 `AIR2_TICK_MAX_SEC`（默认 1800 秒）。

|---|---|---|

| `AIR2_CHARTER` | 内置宪章 | 她的 L0 底线（她不能自己改，你可以） |
| `AIR2_LLM_ENDPOINT` | 见 `config.py` | LLM OpenAI 兼容端点（任意兼容服务都行） |
| `AIR2_LLM_MODEL` | 见 `config.py` | 主模型名（必填） |
| `AIR2_LLM_API_KEY` | 空 | API key（必填；没配会启动即报，不会白转） |
| `AIR2_LLM_THINKING` | `1` | 思考模式开关 |
| `AIR2_LLM_COOLDOWN` | `300` | 主通道熔断冷却秒数 |

## 仪表盘设置页

打开仪表盘，右上角「设置」：LLM / embedding / 搜索 / 订阅源 / 称呼 / 语言 / 宪章都能在这里填。
保存到 `data/settings.json`（不入 git，API key 安全）。**界面语言：刷新页面即切换**；
她的说话语言与其余设置**重启大脑后生效**（大脑进程的配置只在启动时读一次）。
密码框留空保存 = 回退该默认值。

## 网络适配

给不同的网络环境准备的：

- **订阅源 RSS**：默认给 10 个跨地域、稳定的起步源（中文 + 英文科学/哲学/科技，见 `config.py`）。
  想换成自己的：设置页「订阅源 RSS」每行一个地址，或 `AIR2_RSS_FEEDS`。抓不到的源会在
  `read_rss` 返回里单独报出来，不会拖垮其他源。
- **搜索引擎**：默认走无 key 的必应（端点可配）；填了 `AIR2_DEEPSEEK_API_KEY` 会优先走
  DeepSeek 原生 web_search（结构化结果、无反爬坑）。
- **代理**：统一抓取层（`core/fetch.py`）遵循 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`
  环境变量——墙内外互访需要代理时设好这三个变量即可，无需改代码。
- **UA / 语言偏好**：个别站点会拒绝默认 UA（429/403），用 `AIR2_FETCH_UA` 换；
  `AIR2_FETCH_LANG` 调抓取内容的语言偏好。

## 设计思路

### 主循环 tick 生命周期

`core/agent.py` 的 `tick()` 是核心。每轮：

轮询信箱 → 组装基准上下文（宪章 + 相关 L1 自我核心 + 短期记忆 + 来信 + 身体状态）
→ inner loop：LLM 输出带 schema 约束的结构化 JSON → 解析校验（失败回灌重问一次）
→ 分发执行 → 结算（记录"这一步引起了什么变化"）→ 直到她声明 `done`
→ 合成一条目标记录进短期记忆。

**没有候选菜单**：她面对工具清单自己选这一轮做什么。长期方向（set_goal）跨 tick 保留，
"正在读的小说章节"也跨 tick 不丢。

### 唯一的选择面：工具注册表

air 的全部行为来自 `core/tools.py` 的 `_build_tools()`。每条是一个
（action 名，SYSTEM_PROMPT 说明，handler 函数）。**加一个工具只需在注册表追加一条**，
提示词清单和执行分发都自动生成，不用改 agent.py。

### 双驱螺旋的闭环

读世界 → embedding 算向量 → spectrum 按标签聚合出分支分布 → 写记忆/整理时 drive 记账
→ 输出三个读数注入下一轮 prompt。所以"她写了什么、整理了什么"会真实改变她的身体状态。

两本账：熵增账记"写进记忆的料多新"（v_new）；熵减账按压缩事件记（写 L1 / 带方向写 L2/L3 /
删 / 合并 / 改写 = 1，纯堆料 = 0）。读世界不进账，只贴"新奇 X%"的印象分让她自己判断。

### 双进程模型

仪表盘和大脑是两个独立进程，靠 `data/` 下的文件解耦，绝不共享内存：

- 仪表盘写 `mailbox/inbox.jsonl`（你说的话）和 `stop.flag`（停止信号）
- 大脑写 `status.json`（心跳快照）和 `mailbox/outbox.jsonl`（她的话）
- 单实例判断用**内核字节锁**（`core/lock.py`）：加锁是原子的，进程被强杀时 OS 自动释放，
  没有 PID 复用误判、没有残留锁文件。落盘一律走原子写（随机后缀临时文件 + replace 退避重试）。

### 降级设计贯穿全局

这是她"不会停"的韧性来源：LLM 连不上 → 空转不崩；embedding 无服务 → 原地挂机
（在失真数据上做判断比停着更糟，这是刻意的）；画图缺权重、下棋缺库、搜索失败 → 
返回降级提示而非抛异常。写新能力都要遵循这条。

### 记忆的自我维护

L1 三维（价值观 / 世界认知 / 自我认知）各自有下限配额，总数上限 40；
L2 / L3 上限写死。满了由她自己清理（delete / merge）或改写（revise），系统不自动删——
系统只守容量，不替她决定内容。她的决策日志（decisions）供未来提炼价值观。

> 完整机制文档在 `self/`（她的"读自己"文档，纯机制、无解释，agent 运行时按需读取），
> 各模块文件头也有详尽的结构与演进注释。详细的架构演进史设计文档暂未随本仓库发布，
> 将逐步整理进本文档。

## 演进方向（未实现，正在斟酌）

记忆库写满时，熵增路径会减少，只有不断压缩旧记忆才有空间补充新信息，或者行为级熵增。一个待斟酌的设想，是给她一条
**扩张出路**：允许她"发明新工具"来扩展自己的工具箱——而不是只靠开发者手动在
`core/tools.py` 的注册表里加。

为什么还没做：她目前只有 `read_code`（只读），没有运行时改自身代码的安全通道。一个现实点的
中间形态可能是——她先在作品集里用 `write_code` 写工具原型 → 说给 human 听 → human 确认后
才进 `tools.py` 注册表。这样既保住"自主提议"，又不破坏"系统不替她决定、她也改不了护栏"的边界。
